# Рекомендации по дальнейшему развитию

## Markdown

Сейчас предпросмотр детального описания использует библиотеки `marked` и `DOMPurify`, подключенные через CDN в `public/index.html`.

- `marked` преобразует Markdown в HTML;
- `DOMPurify` очищает HTML от опасных тегов и атрибутов перед отображением;
- в базе данных продолжает храниться обычный Markdown в поле `detailsMarkdown`.

Подключены фиксированные версии библиотек, чтобы обновление CDN не меняло поведение приложения неожиданно.

## Перейти на npm

Для production-версии рекомендуется заменить CDN на npm-зависимости:

```bash
npm install marked dompurify
```

После этого библиотеки следует импортировать в клиентский модуль и подключить сборщик, например Vite или esbuild.

Преимущества npm-подхода:

- зависимости фиксируются в `package.json` и `package-lock.json`;
- приложение не зависит от доступности внешнего CDN во время работы;
- версии библиотек контролируются проектом;
- появляется возможность выполнять минификацию, проверку и оптимизацию сборки;
- зависимости можно обновлять контролируемо и проверять в CI.

## Перейти с JSON на СУБД

Сейчас требования и пользователи хранятся в `data/database.json`. Для локального MVP это удобно, но такой способ не рассчитан на несколько одновременных записей и рост данных.

Следующий практичный шаг — SQLite:

- не требует отдельного сервера;
- поддерживает транзакции и ограничения целостности;
- подходит для небольшой внутренней системы;
- проще мигрировать с текущего JSON-хранилища.

Для production-системы с несколькими экземплярами приложения или высокой нагрузкой стоит использовать PostgreSQL.

План миграции:

1. Создать таблицы `users`, `projects`, `requirements`, `user_projects` и `user_permissions`.
2. Перенести существующие записи из `database.json` миграционным скриптом.
3. Заменить `store.js` на repository-слой с SQL-запросами.
4. Добавить миграции схемы и индексы.
5. Настроить резервное копирование и проверку восстановления.

Ключевые ограничения базы данных:

- уникальность логина пользователя;
- уникальность номера требования внутри проекта;
- внешние ключи для проектов и требований;
- допустимые значения ролей и прав;
- автоматические даты создания и изменения записей.
