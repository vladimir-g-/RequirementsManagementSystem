# UC-0008 — Создание связи между требованиями

## Цель

Зафиксировать типизированную связь между двумя требованиями проекта.

## Основной актор

Пользователь

## Триггер

Пользователь открывает карточку требования, чтобы связать его с другим требованием.

## Предварительные условия

- Пользователь аутентифицирован.
- Выбран активный проект.
- Для успешного создания связи пользователь имеет права `read` и `update` в активном проекте; отсутствие хотя бы одного из прав обрабатывается в исключительном сценарии E3.

## Основной сценарий

1. Пользователь открывает карточку исходного требования A.
2. Пользователь находит и выбирает другое требование B того же проекта.
3. Пользователь выбирает тип связи из каталога.
4. Система проверяет допустимость связи и сохраняет её; для направленного типа A является исходным требованием, а B — выбранным связанным требованием.
5. Система показывает связь на карточках обоих требований, сохраняя отношение A к B для направленного типа.

## Исключительные сценарии

### E1 — Требование уже связано с выбранным требованием

1. Этот сценарий выполняется, если при сохранении новой связи система обнаруживает, что выбранная пара требований уже связана.
2. Система отклоняет повторное создание связи независимо от выбранного типа или направления.

### E2 — Недопустимое требование для связи

1. Этот сценарий выполняется, если пользователь выбирает исходное требование в качестве связываемого либо выбирает требование из другого проекта.
2. Система отклоняет создание связи.

### E3 — Недостаточно прав

1. Этот сценарий выполняется, если пользователь не имеет хотя бы одного из прав `read` и `update` в активном проекте и пытается найти требование для создания связи или сохранить новую связь.
2. Система отказывает в доступе к поиску или отклоняет создание связи.
