# UC-0008 — Создание связи между требованиями

## Цель

Зафиксировать типизированную связь между двумя требованиями проекта.

## Основной актор

Пользователь

## Триггер

Пользователь открывает карточку требования, чтобы связать его с другим требованием.

## Предварительные условия

- Пользователь аутентифицирован.
- Выбран активный проект.

## Основной сценарий

1. Пользователь запрашивает карточку исходного требования A; если у него нет права `read` в активном проекте, выполняется исключительный сценарий E3.
2. Система проверяет право `update` в активном проекте; если права нет, выполняется исключительный сценарий E3.
3. Система показывает для выбора требования активного проекта. Пользователь выбирает требование B; если B совпадает с A, выполняется исключительный сценарий E2.
4. Система проверяет, не существует ли уже связь между A и B; если существует, выполняется исключительный сценарий E1.
5. Пользователь выбирает тип связи из каталога.
6. Система сохраняет допустимую связь; для направленного типа A является исходным требованием, а B — выбранным связанным требованием.
7. Система показывает связь на карточках обоих требований, сохраняя отношение A к B для направленного типа.

## Исключительные сценарии

### E1 — Требование уже связано с выбранным требованием

1. Система отклоняет повторное создание связи независимо от выбранного типа или направления.

### E2 — Недопустимое требование для связи

1. Система отклоняет создание связи с самим требованием A.

### E3 — Недостаточно прав

1. Система отказывает в доступе к карточке либо отклоняет поиск и создание связи в соответствии с недостающим правом.
