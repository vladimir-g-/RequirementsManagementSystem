# UC-0002 — Управление требованиями проекта

## Цель

Просматривать и управлять требованиями проекта в пределах прав пользователя.

## Основной исполнитель

Пользователь

## Дополнительные исполнители

- Нет

## Триггер

Пользователь выбирает проект, чтобы просмотреть или изменить его требования.

## Предварительные условия

- Пользователь аутентифицирован.
- Проект существует.

## Основной поток

1. Пользователь выбирает проект.
2. Система проверяет доступ пользователя к проекту и устанавливает его активным.
3. Если у пользователя есть право `read`, система отображает требования проекта; если права `read` нет, выполняется исключительный поток E1.
4. Пользователь выбирает просмотр требований или одно из действий управления ими: поиск, фильтрацию, сортировку, создание, изменение либо удаление.
5. Для выбранного действия выполняется соответствующий альтернативный поток A1–A5; если у пользователя нет необходимого права, выполняется исключительный поток E2.

## Альтернативные потоки

### A1 — Поиск, фильтрация и сортировка требований

1. Этот поток выполняется, если пользователь выбирает поиск, фильтрацию или сортировку требований.
2. Пользователь задаёт критерии поиска, фильтрации или сортировки.
3. Система показывает требования, соответствующие заданным критериям и доступные пользователю.

### A2 — Создание требования

1. Этот поток выполняется, если пользователь выбирает создание требования.
2. Пользователь вводит обязательные данные и при необходимости заполняет дополнительные поля.
3. Система проверяет введённые данные и сохраняет требование, если они допустимы.
4. Система присваивает требованию номер согласно настройкам проекта и типа требования.

### A3 — Изменение требования

1. Этот поток выполняется, если пользователь выбирает существующее требование для изменения.
2. Пользователь изменяет допустимые поля требования.
3. Система проверяет и сохраняет изменения, не меняя присвоенный требованию номер.

### A4 — Удаление требования

1. Этот поток выполняется, если пользователь выбирает удаление требования.
2. Система запрашивает подтверждение удаления.
3. Если пользователь подтверждает удаление, система удаляет требование; если пользователь отменяет действие, система сохраняет данные без изменений.

### A5 — Изменение ширины столбцов

1. Этот поток выполняется, если пользователь изменяет ширину столбца таблицы требований.
2. Пользователь изменяет ширину столбца.
3. Система сохраняет выбранную ширину для пользователя между сеансами.

## Исключительные потоки

### E1 — Нет доступа к проекту или права на чтение

1. Этот поток выполняется, если пользователь выбирает проект, к которому у него нет доступа, либо пытается просмотреть проект без права `read`.
2. Система отказывает в доступе и не отображает требования проекта.

### E2 — Нет права на выбранное действие

1. Этот поток выполняется, если пользователь инициирует создание, изменение или удаление требования, не имея соответственно права `create`, `update` или `delete`.
2. Система отклоняет действие и не изменяет данные.

## Состояние после выполнения

- При успешном просмотре пользователь видит только доступные ему требования проекта.
- При успешном изменении система сохраняет запрошенные изменения; при удалении пользователь подтверждает действие.
- При отказе в доступе или отмене удаления данные остаются без изменений.
