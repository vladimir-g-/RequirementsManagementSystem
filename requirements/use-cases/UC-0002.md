# UC-0002 — Управление требованиями проекта

## Goal

Работать с требованиями проекта, к которым пользователь имеет доступ по своим правам.

## Primary actor

Пользователь

## Триггер

Пользователь выбирает проект, чтобы просмотреть или изменить его требования.

## Предварительные условия

- Пользователь аутентифицирован.
- Пользователю доступен хотя бы один проект.
- В проекте может существовать набор требований и групп.

## Main flow

1. Пользователь выбирает проект, к которому у него есть доступ.
2. Система отображает требования, доступные пользователю для чтения.
3. Пользователь при необходимости выполняет поиск, фильтрацию или сортировку списка требований.
4. Пользователь создаёт, изменяет или удаляет требование в пределах своих прав доступа.
5. При создании требования система назначает номер в соответствии с настройками проекта.

## Alternative flows

### A1 — Поиск, фильтрация и сортировка

1. Пользователь задаёт критерии поиска, фильтрации или сортировки.
2. Система обновляет представление требований в соответствии с выбранными параметрами.
3. Пользователь продолжает рассмотрение или редактирование найденных элементов.

### A2 — Создание или изменение требования

1. Пользователь инициирует создание или редактирование требования.
2. Система валидирует введённые данные и сохраняет изменение, если оно допустимо.
3. Обновлённое требование становится доступным в соответствующем проекте.

## Exception flows

### E1 — Нет доступа к проекту или требованию

1. Пользователь пытается открыть проект или изменить требование, на которое у него нет прав.
2. Система ограничивает доступ и показывает соответствующее предупреждение.

### E2 — Запрещённое действие над требованием

1. Пользователь пытается удалить или изменить требование вне допустимого сценария.
2. Система отклоняет действие и сохраняет текущее состояние данных без изменений.
