# UC-0015 — Управление списком проектов

## Goal

Поддерживать актуальный список проектов: создавать проекты, изменять их названия и коды, а также удалять пустые проекты.

## Primary actor

Администратор

## Триггер

Администратор открывает пункт «Проекты» в меню «Администрирование» и выбирает операцию с проектом.

## Предварительные условия

- Администратор аутентифицирован.
- Администратор имеет системную роль «Администратор».

## Main flow

1. Администратор выбирает пункт «Проекты» в меню «Администрирование». Система открывает форму управления проектами и отображает список всех проектов с названием и кодом каждого проекта.
2. Администратор выбирает операцию: создать проект, изменить проект или удалить проект.
3. Если выбрано создание, администратор вводит название и код проекта. Система проверяет, что оба значения заполнены, название содержит не более 200 символов и состоит из печатных символов, название и код уникальны без учёта регистра среди других проектов, а код соответствует формату, установленному в BRL-0011; если проверка не пройдена, выполняется исключительный сценарий E1; иначе система сохраняет проект и отображает его в списке.
4. Если выбрано изменение, администратор выбирает проект и вводит новое название, а для проекта без требований и групп может также ввести новый код. Система проверяет, что новое название непустое, содержит не более 200 символов, состоит из печатных символов и уникально среди других проектов, а если код изменяется — что он уникален среди других проектов и соответствует формату, установленному в BRL-0011; если проверка не пройдена, выполняется исключительный сценарий E1; если администратор пытается изменить код проекта, содержащего требования или группы, выполняется исключительный сценарий E2; иначе система сохраняет изменения.
5. Если выбрано удаление, система проверяет, содержит ли проект требования или группы. Если содержит, выполняется исключительный сценарий E3; если не содержит, система удаляет проект, доступ пользователей к этому проекту, права доступа к нему и настройки префиксов номеров требований для этого проекта, а затем обновляет список проектов; если удалённый проект был активным, система отображает состояние без активного проекта до явного выбора проекта пользователем, при этом требования и группы не отображаются.
6. Если администратор отменяет операцию до сохранения, выполняется альтернативный сценарий A1.

## Alternative flows

### A1 — Отмена операции

1. Система сохраняет текущее состояние проекта и списка проектов без изменений.

## Исключительные сценарии

### E1 — Некорректные или неуникальные данные проекта

1. Система отклоняет сохранение и сообщает об ошибке.
2. Введённые данные остаются в форме; существующий проект не изменяется, а новый проект не создаётся.

### E2 — Попытка изменить код проекта, содержащего требования или группы

1. Система отклоняет изменение кода и сохраняет прежний код проекта.
2. Остальные данные проекта сохраняются без изменений.

### E3 — Попытка удалить проект, содержащий требования или группы

1. Система отклоняет удаление.
2. Проект, его требования и группы сохраняются без изменений.

## Postconditions

- Созданный проект сохранён и отображается в списке проектов; он доступен для назначения пользователям.
- Изменённые название и/или код проекта сохранены; код изменён только у проекта без требований и групп.
- Удалённый проект отсутствует в списке и не может быть выбран; доступ пользователей к проекту, права доступа к нему и настройки префиксов номеров требований для этого проекта удалены; требования, группы и другие проекты не изменены.
- Если удалённый проект был активным, активный проект не выбран; требования и группы не отображаются до явного выбора проекта пользователем.
- При отклонённой операции проект и список проектов не изменены.
