# UC-0013 — Просмотр карточки требования

## Цель

Просмотреть данные выбранного требования и его связи; при наличии права `update` — изменить требование и его связи.

## Основной актор

Пользователь

## Триггер

Пользователь выбирает требование в списке требований активного проекта согласно [UC-0002](UC-0002.md).

## Предварительные условия

- Пользователь аутентифицирован.
- Выбран активный проект.
- Список требований получен по [UC-0002](UC-0002.md); пользователь имеет право `read` в активном проекте.
- Требование принадлежит активному проекту.

## Основной поток

1. Пользователь открывает карточку выбранного требования; если требование к этому моменту удалено, выполняется исключительный поток E1.
2. Система отображает номер, краткое описание, подробное описание, группу, тип, важность, сложность, статус и релиз требования.
3. Система отображает связи требования с указанием связанных требований и типов связей. Для каждой направленной связи система явно показывает, какое требование является A, а какое — B, сохраняя смысл отношения A к B независимо от того, с какой карточки пользователь просматривает связь.
4. Если у пользователя есть право `update` в активном проекте, система открывает карточку в режиме изменения: значения полей доступны для изменения и отображается действие сохранения. Если права `update` нет, карточка открывается в режиме просмотра: значения полей недоступны для изменения, действие сохранения не отображается.
5. Если у пользователя есть право `update`, система отображает в блоке связей поиск требования, выбор типа связи, действие добавления связи и действия удаления связей. Если права `update` нет, система отображает только список существующих связей.

## Исключительные потоки

### E1 — Требование не найдено

1. Система сообщает, что требование не найдено, и не отображает карточку.
