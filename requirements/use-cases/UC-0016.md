# UC-0016 — Управление списком типов требований

## Goal

Поддерживать актуальный справочник типов требований: создавать типы, изменять их названия и удалять типы, не используемые ни одним требованием ни в одном проекте.

## Primary actor

Администратор

## Триггер

Администратор открывает пункт «Типы требований» в меню «Администрирование» и выбирает операцию с типом требования.

## Предварительные условия

- Администратор аутентифицирован.
- Администратор имеет системную роль «Администратор».

## Main flow

1. Администратор выбирает пункт «Типы требований» в меню «Администрирование». Система открывает форму управления списком типов требований и отображает список всех типов требований.
2. Администратор выбирает операцию: создать тип, изменить тип или удалить тип.
3. Если выбрано создание, администратор вводит название типа. Система проверяет, что название заполнено, имеет длину не более 50 символов и уникально без учёта регистра среди других типов; если проверка не пройдена, выполняется исключительный сценарий E1; иначе система сохраняет тип требования и отображает его в списке.
4. Если выбрано изменение, администратор выбирает тип и вводит новое название. Система проверяет, что название заполнено, имеет длину не более 50 символов и уникально без учёта регистра среди других типов; если проверка не пройдена, выполняется исключительный сценарий E1; иначе система сохраняет новое название; новое название отображается у всех существующих требований данного типа, а настройки префиксов номеров требований для пар «проект — тип» этого типа сохраняются без изменений.
5. Если выбрано удаление, система проверяет, что тип не используется ни одним требованием ни в одном проекте. Если используется хотя бы одним требованием, выполняется исключительный сценарий E2; если не используется, система удаляет тип требования, настройки префиксов номеров требований для всех пар «проект — тип», содержащих этот тип, а затем обновляет список типов требований.
6. Если администратор отменяет операцию до сохранения, выполняется альтернативный сценарий A1.

## Alternative flows

### A1 — Отмена операции

1. Система сохраняет текущее состояние типа и списка типов требований без изменений.

## Исключительные сценарии

### E1 — Некорректное или неуникальное название типа

1. Система отклоняет сохранение и сообщает об ошибке.
2. Введённые данные остаются в форме; существующий тип не изменяется, а новый тип не создаётся.

### E2 — Попытка удалить тип, используемый требованиями

1. Система отклоняет удаление и сообщает, что тип используется требованиями.
2. Тип требования, список типов и настройки префиксов сохраняются без изменений.

## Postconditions

- Созданный тип требования сохранён и отображается в списке типов; тип доступен для выбора при создании и изменении требований.
- Изменённое название типа сохранено и отображается у всех существующих требований данного типа; настройки префиксов не изменены.
- Удалённый тип отсутствует в списке и не может быть выбран; настройки префиксов для пар «проект — тип» этого типа удалены; требования, проекты и настройки префиксов для других типов не изменены.
- При отклонённой операции типы и список типов не изменены.
