# UC-0014 — Самостоятельная смена пароля

## Goal

Изменить пароль собственной учётной записи.

## Primary actor

Пользователь

## Триггер

Пользователь открывает форму профиля и выбирает смену пароля.

## Предварительные условия

- Пользователь аутентифицирован.

## Main flow

1. Пользователь открывает форму своего профиля.
2. Пользователь нажимает отдельную кнопку «Изменить пароль».
3. Система открывает отдельную форму ввода нового пароля и его повторного ввода; поле для текущего пароля не запрашивается.
4. Если пользователь отказывается от смены пароля, он закрывает форму без отправки; система выполняет альтернативный сценарий A1.
5. Если пользователь продолжает смену, он вводит новый пароль и повторяет его.
6. Пользователь отправляет форму; система проверяет значения по правилу валидации [VR-0003](../validation-rules/VR-0003.md): если хотя бы одно значение пустое, выполняется исключительный сценарий E1; по правилу валидации [VR-0007](../validation-rules/VR-0007.md): если значения не совпадают, выполняется исключительный сценарий E2.
7. Система сохраняет новый пароль для учётной записи пользователя; если сохранить его не удалось, выполняется исключительный сценарий E3.
8. После сохранения пароля система пытается завершить каждый активный сеанс учётной записи отдельно. Для каждого завершённого сеанса система отображает форму входа; если отдельный сеанс завершить не удалось, выполняется исключительный сценарий E4 для этого сеанса.
9. Пользователь может войти в завершённый сеанс, используя новый пароль.

## Alternative flows

### A1 — Пользователь отменяет смену пароля

1. Система закрывает отдельную форму смены пароля и возвращает пользователя к форме профиля.
2. Пароль учётной записи и активные сеансы остаются без изменений.

## Исключительные сценарии

### E1 — Не введён новый пароль или его повтор

1. Система отклоняет запрос и отображает текстовое сообщение о том, что оба поля обязательны.
2. Существующий пароль и активные сеансы остаются без изменений.
3. Пользователь может исправить ввод и повторить отправку формы.

### E2 — Значения нового пароля не совпадают

1. Система отклоняет запрос и отображает текстовое сообщение о несовпадении значений.
2. Существующий пароль и активные сеансы остаются без изменений.
3. Пользователь может исправить ввод и повторить отправку формы.

### E3 — Система не может сохранить новый пароль

1. Система отображает текстовое сообщение об ошибке, объясняющее, что новый пароль не сохранён.
2. Существующий пароль и текущий сеанс остаются без изменений.
3. Пользователь может повторить попытку.

### E4 — Система не может завершить все активные сеансы

1. В каждом незавершённом сеансе система отображает пользователю текстовое сообщение об ошибке, объясняющее, что этот сеанс не удалось завершить после смены пароля.
2. Система оставляет незавершённый сеанс активным и сохраняет в нём текущее состояние интерфейса.
3. В остальных сеансах, которые система успешно завершила, отображается форма входа.

## Postconditions

- После успешного сохранения новый пароль установлен для учётной записи пользователя. Сеансы, завершение которых прошло успешно, больше не аутентифицированы и показывают форму входа; сеансы, завершить которые не удалось, остаются активными в текущем состоянии интерфейса.
- При отказе валидации или сохранения пароль остаётся прежним.
