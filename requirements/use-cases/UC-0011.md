# UC-0011 — Изменение требования

## Цель

Изменить данные существующего требования, сохранив его номер.

## Основной актор

Пользователь

## Триггер

Пользователь инициирует изменение требования в активном проекте.

## Предварительные условия

- Пользователь аутентифицирован.
- Выбран активный проект.
- Требование принадлежит активному проекту.
- Пользователь имеет право `update` (изменение) в активном проекте.

## Основной сценарий

1. Пользователь выбирает требование и инициирует его изменение.
2. Система предоставляет возможность изменить данные требования.
3. Пользователь изменяет одно или несколько полей требования и сохраняет изменения.
4. Система проверяет введённые данные; если значения допустимы, система сохраняет изменения, не изменяя номер требования.
5. Система сообщает об успешном изменении требования.

## Альтернативные сценарии

### A1 — Пользователь отменяет изменение

1. Этот сценарий выполняется, если пользователь отменяет изменение до сохранения.
2. Система сохраняет исходные данные требования без изменений.

## Исключительные сценарии

### E1 — Недопустимые данные требования

1. Этот сценарий выполняется, если при проверке на шаге 4 система обнаруживает недопустимое значение или группу, не принадлежащую активному проекту.
2. Система отклоняет изменения и сообщает о причине; исходные данные требования остаются без изменений.

### E2 — Недостаточно прав

1. Этот сценарий выполняется, если пользователь без права `update` пытается изменить или сохранить требование.
2. Система отклоняет изменение и сохраняет исходные данные требования.
