# UC-0011 — Изменение требования

## Цель

Изменить данные существующего требования, сохранив его номер.

## Основной актор

Пользователь

## Триггер

Пользователь инициирует изменение требования в активном проекте.

## Предварительные условия

- Пользователь аутентифицирован.
- Выбран активный проект.
- Требование принадлежит активному проекту.

## Основной поток

1. Пользователь выбирает в списке требований активного проекта требование, которое хочет изменить.
2. Система проверяет, что у пользователя есть право `update` (изменение) в активном проекте; если права нет, система не предоставляет возможность изменения через пользовательский интерфейс, а запрос на изменение, поступивший в обход интерфейса, отклоняется по исключительному потоку E2.
3. Система открывает форму изменения требования с текущими значениями полей.
4. Если пользователь отменяет изменение до сохранения, выполняется альтернативный поток A1; иначе пользователь изменяет одно или несколько полей требования и сохраняет изменения.
5. Система проверяет, что тип, важность и статус входят в соответствующие системные справочники по правилу валидации [VR-0002](../validation-rules/VR-0002.md), а выбранная группа принадлежит активному проекту; если проверка не пройдена, выполняется исключительный поток E1.
6. Если все проверки пройдены и сохранение не перезапишет параллельно сохранённые изменения, система сохраняет изменения, не изменяя номер требования; если требуется перезаписать такие изменения, выполняется исключительный поток E3.
7. Система сообщает об успешном изменении требования.

## Альтернативные потоки

### A1 — Пользователь отменяет изменение

1. Система прекращает редактирование, не сохраняя введённые изменения.
2. Система отображает данные требования в состоянии до начала редактирования.

## Исключительные потоки

### E1 — Недопустимые данные требования

1. Система отклоняет изменения, сообщает о причине; данные требования остаются без изменений.

### E2 — Нет права на изменение

1. Система отклоняет изменение, сообщает об отсутствии права на изменение; данные требования остаются без изменений.

### E3 — Конфликт параллельных изменений

1. Система отклоняет устаревшее изменение, сообщает пользователю о конфликте; ранее записанные данные остаются без изменений.
