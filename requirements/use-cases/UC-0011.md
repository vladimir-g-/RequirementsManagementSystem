# UC-0011 — Изменение требования

## Цель

Изменить данные существующего требования, сохранив его номер.

## Основной актор

Пользователь

## Триггер

Пользователь инициирует изменение требования в активном проекте.

## Предварительные условия

- Пользователь аутентифицирован.
- Выбран активный проект.
- Требование принадлежит активному проекту.

## Основной сценарий

1. Пользователь инициирует изменение требования; если у него нет права `update` в активном проекте, выполняется исключительный сценарий E2.
2. Пользователь выбирает требование для изменения. Способ выбора при отсутствии права `read` не определён ([OQ-0006](../questions/OQ-0006.md)).
3. Система предоставляет возможность изменить данные требования.
4. Если пользователь отменяет изменение до сохранения, выполняется альтернативный сценарий A1; иначе пользователь изменяет одно или несколько полей требования и сохраняет изменения.
5. Система проверяет, что тип, важность и статус входят в соответствующие системные справочники, а выбранная группа принадлежит активному проекту; если проверка не пройдена, выполняется исключительный сценарий E1.
6. Если все проверки пройдены, система сохраняет изменения, не изменяя номер требования.
7. Система сообщает об успешном изменении требования.

## Альтернативные сценарии

### A1 — Пользователь отменяет изменение

1. Система сохраняет исходные данные требования без изменений.

## Исключительные сценарии

### E1 — Недопустимые данные требования

1. Система отклоняет изменения, сообщает о причине и сохраняет исходные данные требования без изменений.

### E2 — Недостаточно прав

1. Система отклоняет изменение и сохраняет исходные данные требования.
