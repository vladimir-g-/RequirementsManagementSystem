# OQ-0008 — Ограничения названия и кода проекта

## Статус

Resolved (Решен)

## Вопрос

Какие ограничения по длине и допустимым символам должны действовать для названия проекта и нужно ли устанавливать для кода проекта более строгий формат, чем формат префикса номера требования?

## Контекст

Уникальность названия и кода без учёта регистра, а также условия изменения кода определены. Код проекта должен соответствовать формату префикса номера требования, поэтому он пригоден для формирования номеров. Базовый допустимый формат кода задан в [BRL-0011](../business-rules/BRL-0011.md) и совпадает с форматом префикса из [BRL-0004](../business-rules/BRL-0004.md). На момент постановки вопроса не были установлены максимальная длина и допустимые символы названия, а также необходимость более строгого формата кода; без решения вопроса об ограничениях названия критерии создания и изменения проекта нельзя было проверить полностью.

Текущие проекты имеют коды из трёх заглавных латинских букв, однако это может быть характеристикой существующих данных, а не правилом.

## Связанные требования

- [BRL-0011](../business-rules/BRL-0011.md)
- [FR-0029](../functional/FR-0029.md)
- [FR-0030](../functional/FR-0030.md)
- [FR-0031](../functional/FR-0031.md)
- [AC-0020](../acceptance-criteria/AC-0020.md)

## Возможные варианты

### Вариант A

Название проекта — непустое, длиной до 200 символов, любые печатные символы. Код проекта — в формате префикса номера требования ([BRL-0004](../business-rules/BRL-0004.md)).

**Последствия:**

- Код всегда пригоден для использования в качестве префикса номера требования.
- Потребуется проверка длины и символов названия; код проверяется по формату префикса.

### Вариант B

Название проекта — непустое, длиной до 100 символов. Код проекта — ровно три заглавные латинские буквы.

**Последствия:**

- Правило соответствует формату существующих кодов проектов.
- Возможности выбора кода проекта ограничены, а существующие проекты с другими кодами потребуют отдельного решения.

### Вариант C

Не устанавливать ограничений длины и допустимых символов для названия, кроме непустоты. Код проекта должен соответствовать формату префикса номера требования.

**Последствия:**

- Название проекта может быть неограниченно длинным и содержать любые символы, что усложняет отображение в интерфейсе.
- Для кода не устанавливается более строгий формат, чем формат префикса.

## Решение

Вариант A: название проекта непустое, длиной не более 200 символов, может содержать любые печатные символы. Код проекта соответствует формату префикса номера требования, установленному в [BRL-0004](../business-rules/BRL-0004.md). Уникальность названия и кода без учёта регистра сохраняется.
