# OQ-0009 — Активный проект после удаления

## Статус

Resolved (Решен)

## Вопрос

Какое состояние должна отображать система после удаления проекта, который был выбран активным в текущем сеансе администратора?

## Контекст

Удаление проекта разрешено только при отсутствии в нём требований и групп, а удалённый проект не должен отображаться в списке и не может быть выбран. При этом активный проект определяет контекст работы с требованиями. На момент постановки вопроса поведение системы, если удаляется именно активный проект, не было определено; без этого решения нельзя было проверить корректность состояния интерфейса после удаления.

## Возможные варианты

### Вариант A

Система автоматически выбирает другой доступный проект; если доступных проектов нет, отображается состояние без активного проекта.

**Последствия:**

- Пользователь может продолжить работу без дополнительного выбора.
- Требуется определить правило выбора проекта, например первый доступный в списке.

### Вариант B

Система отображает состояние без активного проекта до явного выбора пользователем.

**Последствия:**

- Пользователь явно выбирает дальнейший контекст работы.
- Требования и группы не отображаются, пока проект не выбран.

### Вариант C

Система запрещает удаление проекта, пока он выбран активным в текущем сеансе.

**Последствия:**

- Администратор должен сначала выбрать другой проект.
- Удаление зависит от состояния текущего сеанса, а не только от данных проекта.

## Решение

Вариант B: после удаления активного проекта система отображает состояние без активного проекта до явного выбора проекта пользователем. Требования и группы не отображаются, пока проект не выбран.
