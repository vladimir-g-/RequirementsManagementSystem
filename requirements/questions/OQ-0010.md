# OQ-0010 — Исходный состав справочника типов требований

## Статус

Resolved (Решен)

## Вопрос

Должен ли справочник типов требований содержать предустановленный набор типов при первоначальной настройке, как каталог типов связей ([FR-0020](../functional/FR-0020.md)), и каким должен быть этот набор?

## Контекст

Правила создания, изменения и удаления типов определены ([FR-0033](../functional/FR-0033.md)–[FR-0036](../functional/FR-0036.md), [BRL-0013](../business-rules/BRL-0013.md), [BRL-0014](../business-rules/BRL-0014.md)). Требования уже используют типы как справочные значения ([VR-0002](../validation-rules/VR-0002.md)), однако исходный состав справочника типов требований не установлен. Без решения нельзя полностью проверить первоначальную настройку формы управления типами требований.

## Связанные требования

- [FR-0036](../functional/FR-0036.md)

## Возможные варианты

### Вариант A

Справочник изначально пуст; все типы требований создаются администратором через форму управления.

**Последствия:**

- Не требуется согласовывать предустановленный состав.
- Администратору необходимо вручную наполнить справочник до использования системы.

### Вариант B

Справочник содержит предустановленный набор типов, согласованный отдельно (по аналогии с каталогом типов связей).

**Последствия:**

- Система готова к работе сразу после развёртывания.
- Требуется отдельное согласование состава и названий типов.

### Вариант C

Исходный состав формируется из типов, уже существующих в данных текущей системы.

**Последствия:**

- Состав отражает фактическое использование.
- Требуется анализ существующих данных и решение о недопустимых или дублирующихся значениях.

## Решение

Вариант B: справочник типов требований содержит предустановленный набор типов при первоначальной настройке. Исходный состав:

1. Функциональное
2. Нефункциональное
3. Сценарий использования
4. Пользовательская история
5. Бизнес-требование
