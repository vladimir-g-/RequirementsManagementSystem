## Критерии

| # | Дано | Когда | Тогда |
|---|---|---|---|
| 1 | Пользователь аутентифицирован и имеет системную роль «Администратор». | Пользователь открывает пункт «Типы требований» в меню «Администрирование». | Система отображает форму со списком всех типов требований и элементами управления для создания, изменения и удаления типов. |
| 2 | Пользователь аутентифицирован и не имеет системной роли «Администратор». | Пользователь просматривает меню или пытается открыть форму управления типами требований. | Система не отображает пункт «Типы требований» и отклоняет попытку открыть административную форму. |
| 3 | Администратор открыл форму управления типами требований. | Администратор создаёт тип требования с непустым названием длиной не более 50 символов, уникальным без учёта регистра среди других типов. | Система сохраняет тип и отображает его в списке типов. |
| 4 | Администратор открыл форму управления типами требований. | Администратор пытается создать тип с пустым названием, с названием длиной более 50 символов или с названием, совпадающим с названием другого типа без учёта регистра. | Система отклоняет создание и сообщает об ошибке; новый тип не создаётся, введённые данные остаются в форме. |
| 5 | Тип используется хотя бы одним требованием в каком-либо проекте. | Администратор изменяет название типа на непустое название длиной не более 50 символов, уникальное без учёта регистра. | Система сохраняет новое название; новое название отображается у всех существующих требований данного типа; нумерация требований и настройки префиксов не изменяются. |
| 6 | Администратор изменяет название типа. | Администратор указывает пустое название, название длиной более 50 символов или название, совпадающее с названием другого типа без учёта регистра. | Система отклоняет изменение и сообщает об ошибке; прежнее название типа сохраняется. |
| 7 | Тип используется хотя бы одним требованием в каком-либо проекте. | Администратор пытается удалить тип. | Система отклоняет удаление и сообщает, что тип используется требованиями; тип, список типов и настройки префиксов сохраняются без изменений. |
| 8 | Тип не используется ни одним требованием ни в одном проекте. | Администратор удаляет тип. | Система удаляет тип; удалённый тип не отображается в списке и не может быть выбран; настройки префиксов для всех пар «проект — тип», содержащих этот тип, удаляются; требования, проекты и настройки префиксов для других типов не изменяются. |
| 9 | Пользователь аутентифицирован и не имеет системной роли «Администратор». | Пользователь получает типы требований для выбора при создании или изменении требования и пытается создать, переименовать или удалить тип. | Система возвращает список типов для выбора и отклоняет операции изменения справочника. |
