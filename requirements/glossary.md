# Глоссарий

| Термин | Определение |
|---|---|
| Администратор | Роль системы с доступом ко всем настроенным проектам и административным возможностям, описанным для MVP. |
| Активный проект | Проект, выбранный пользователем как текущий контекст работы с требованиями и группами. Если активный проект не выбран, требования и группы не отображаются до явного выбора проекта. |
| Группа | Элемент структуры, принадлежащий проекту и содержащий требования и дочерние группы. |
| Право доступа | Разрешение на операцию (`create` — создание, `read` — чтение, `update` — изменение, `delete` — удаление), назначаемое в рамках проекта. |
| Назначение проекта | Предоставление пользователю доступа к проекту; в рамках назначенного проекта пользователю отдельно назначаются права на требования. Для роли администратора назначение проектов не требуется. |
| Проект | Отдельная область работ, имеющая уникальные название и код; требования и группы которой ведутся в системе. |
| Код проекта | Уникальный без учёта регистра идентификатор проекта, используемый при формировании номеров требований, если для пары «проект — тип» не настроен префикс. Задаётся при создании проекта и изменяется только у проекта без требований и групп. |
| Пустой проект | Проект, не содержащий ни требований, ни групп. |
| Требование | Зафиксированное утверждение, управляемое в рамках проекта. |
| Номер требования | Идентификатор требования, формируемый системой из настроенного префикса и порядкового номера. |
| Тип требования | Справочное значение общего для системы справочника, управляемого администратором. Используется для классификации требования и определения области его нумерации. Название типа — не более 50 символов; тип может быть удалён, только пока не используется ни одним требованием ни в одном проекте. |
| Тип связи требований | Значение общего для проектов каталога, определяющее смысл и направленность связи между требованиями. |
| Связь требований | Явно заданное отношение между двумя разными требованиями одного проекта, которому назначен тип связи. |
| Пользователь | Аутентифицированный человек, работающий в системе с назначенной ролью и правами доступа к проектам. Пользователь может быть создан без доступа к проектам; доступ и права назначаются отдельно. |
| Рабочая область | Общий контекст системы, содержащий проекты. На текущем этапе используется одна общая рабочая область; доступ к проектам разграничивается отдельно. |
