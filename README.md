# Requirements Management System

Веб-приложение для управления требованиями по проектам.

**ВНИМАНИЕ** - пока это MVP!

Возможности:

- вход аутентифицированного пользователя;
- выбор проекта и просмотр его требований;
- изменение ширины столбцов таблицы требований с сохранением настройки для пользователя;
- создание, редактирование и удаление требований;
- создание, редактирование и удаление иерархических групп требований; создание дочерней группы доступно кнопкой «+» рядом с редактированием группы;
- привязка требования к одной группе или отвязка от группы;
- фильтрация по статусу и поиск по номеру, описанию и типу;
- роли `Администратор` и `Пользователь`;
- назначение пользователям проектов и отдельных прав на требования;
- интерфейс управления пользователями доступен администраторам;
- создание, просмотр и удаление связей между требованиями; администратор управляет общим каталогом типов связей;
- хранение данных в `data/database.json`.

Справочники интерфейса вынесены в отдельные JSON-файлы в `public/config`:

- `statuses.json` — статусы;
- `priorities.json` — приоритеты;
- `complexities.json` — сложности;
- `types.json` — типы требований;
- `projects.json` — проекты.

Типы требований хранятся в `types.json` как записи с постоянными `id` и отображаемым `name`. Чтобы добавить тип, добавьте запись с новым уникальным `id`; для переименования измените только `name`, не меняя `id`. Требования и префиксы ссылаются на тип по `id`.

Справочники читаются сервером и доступны через `GET /api/config`. Клиент загружает их через `public/modules/config.js`.

Права пользователя: `create`, `read`, `update`, `delete`. Пользователь видит и изменяет требования только в назначенных проектах.

Связи создаются между разными требованиями одного проекта. Создание и удаление связей требуют прав `read` и `update`; просмотр существующих связей доступен при праве `read`. Между одной парой требований допускается только одна связь. Типы связей и их направленность настраиваются администратором в меню **Администрирование → Типы связей**; удаление типа удаляет все связи этого типа, но не требования.

Группы принадлежат проекту и могут иметь подгруппы любой глубины. При выборе группы в дереве отображаются требования этой группы и всех её дочерних групп. Удаление требует подтверждения пользователя; удалить можно только группу без требований и дочерних групп. Права на группы используют права проекта: `create`, `update` и `delete`.

Номера требований формируются сервером автоматически в формате `ПРЕФИКС-001`. Префикс задаётся администратором отдельно для каждой пары `проект + тип требования`, а числовая часть увеличивается в рамках этой пары. Настройка доступна в меню администратора: **Префиксы требований**.

Рекомендации по дальнейшему развитию: [docs/future-recommendations.md](docs/future-recommendations.md).

## Run

```bash
npm start
```

The server starts at `http://localhost:3000`.

Тестовый пользователь: `admin` / `admin123`.

For development with automatic restarts:

```bash
npm run dev
```
